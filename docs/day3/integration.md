# Системное программирование и интеграция

**Проект:** «Записная книжка контактов».

**Вариант:** 14.

## 1. Цель работы

Реализовать локальное хранение контактных данных и обеспечить взаимодействие слоя данных с бизнес-логикой приложения.

## 2. Выбор механизма интеграции

Для хранения контактов используются SharedPreferences и формат JSON.

Данный механизм позволяет сохранять контактные данные во внутреннем хранилище приложения без использования внешней базы данных и подключения к интернету.

## 3. Структура данных

Каждый контакт содержит следующие поля:

| Поле | Тип данных | Назначение |
|---|---|---|
| id | Int | Уникальный идентификатор |
| name | String | Имя контакта |
| phone | String | Номер телефона |

## 4. Операции с данными

| Операция | Назначение |
|---|---|
| save | Сохранение списка контактов в формате JSON |
| load | Загрузка сохранённых контактов |
| search | Поиск контактов по имени или номеру телефона |
| delete | Удаление контакта и сохранение обновлённого списка |

В таблице представлены логические операции приложения.

## 5. Интеграция с бизнес-логикой

При запуске приложения выполняется загрузка сохранённых контактов.

При добавлении или удалении контакта список обновляется, преобразуется в формат JSON и сохраняется с помощью SharedPreferences.

Поиск выполняется по загруженному списку контактов.

## 6. Проверка работоспособности

| Сценарий | Результат |
|---|---|
| Добавление контакта | Успешно |
| Сохранение данных | Успешно |
| Загрузка контактов после перезапуска | Успешно |
| Поиск сохранённого контакта | Успешно |
| Удаление контакта | Успешно |
| Отображение пустого списка | Успешно |

## 7. Вывод

Реализован механизм локального хранения контактных данных с использованием SharedPreferences и JSON. Выполнена интеграция хранения данных с бизнес-логикой приложения. Проверено сохранение контактов после перезапуска.
