# Анализ рисков проекта

**Название проекта:** «Записная книжка контактов».

**Вариант:** 14.

## 1. Цель анализа рисков

Определение возможных проблем при разработке мобильного приложения, оценка их влияния на проект и подготовка мероприятий по предотвращению и устранению ошибок.

## 2. Реестр рисков

| ID | Описание риска | Вероятность | Влияние | Способ предотвращения или устранения |
|---|---|---|---|---|
| R-01 | Ошибки сборки приложения | Высокая | Высокое | Проверка настроек Gradle и среды разработки |
| R-02 | Потеря исходного кода | Низкая | Высокое | Резервное копирование и использование GitHub |
| R-03 | Потеря сохранённых контактов | Средняя | Высокое | Использование SharedPreferences и проверка сохранения данных после перезапуска |
| R-04 | Некорректный ввод данных | Высокая | Среднее | Проверка имени и номера телефона перед сохранением |
| R-05 | Ошибки поиска контактов | Средняя | Среднее | Ручное и автоматизированное тестирование |
| R-06 | Проблемы подключения смартфона | Средняя | Высокое | Проверка USB-подключения, настроек отладки и ADB |
| R-07 | Нарушение сроков разработки | Средняя | Высокое | Планирование задач и последовательное выполнение этапов |
| R-08 | Ошибки пользовательского интерфейса | Средняя | Среднее | Проверка отображения элементов на физическом устройстве |
| R-09 | Ошибки запуска модульных тестов | Средняя | Высокое | Проверка настроек Gradle и пути к кэшу |
| R-10 | Неполное оформление документации | Средняя | Среднее | Проверка соответствия документации индивидуальному заданию |

## 3. Возникшие проблемы и их устранение

| Проблема | Решение | Результат |
|---|---|---|
| Ошибка запуска модульных тестов Gradle | Изменение пути к кэшу Gradle на C:\GradleCache | Все 5 модульных тестов успешно пройдены |
| Android Studio не обнаруживает смартфон | Перезапуск ADB и установка APK через терминал | Приложение успешно установлено на устройство |
| Некорректное отображение архитектурных диаграмм на GitHub | Исправление синтаксиса Mermaid | Диаграммы отображаются корректно |

## 4. Мероприятия по снижению рисков

- Регулярное сохранение исходного кода на GitHub.
- Проверка работоспособности приложения после изменений.
- Ручное и автоматизированное тестирование.
- Использование физического Android-устройства для проверки приложения.
- Подготовка резервных копий проекта.
- Ведение технической документации.

## 5. Вывод

Определены десять основных рисков проекта и способы их снижения. Возникшие технические проблемы успешно устранены. По результатам проведённого тестирования подтверждена работоспособность основных функций мобильного приложения «Записная книжка контактов».
